# M4.0 - Core Platform Specifications

## Obiettivo

Definire le specifiche documentali della piattaforma core plugin-first prima di
scrivere altro codice applicativo o introdurre plugin dominio.

Questa milestone serve a trasformare la visione architetturale in contratti
leggibili: cosa resta nel core, come i plugin vengono dichiarati, caricati,
protetti, isolati, osservati ed estesi nel backoffice.

## Perimetro

- specifica dei confini Trinacria framework / CMS kernel / core-pack / plugin dominio
- specifica del contratto plugin CMS
- specifica runtime plugin e lifecycle operativo
- specifica security core, capability, permission e provisioning
- specifica Mongo storage core: namespace, entity registry, repository contract e
  isolamento plugin
- specifica configuration registry e secrets core
- specifica namespace governance, alias e collision policy
- specifica plugin event bus opzionale basato sulle primitive Trinacria
- specifica admin extensibility core
- specifica installation/bootstrap core
- specifica packaging, discovery e compatibilita plugin
- specifica observability, diagnostics e operation log
- specifica API/SDK contract
- riallineamento dei task M4/M5 alla nuova lettura core-platform

## Fuori perimetro

- implementazione di plugin dominio
- specifiche prodotto editoriali, commerce, media, SEO o altri domini
- modifica di controller, repository o SDK
- generazione automatica UI da schema
- migrazione delle pagine backoffice esistenti
- introduzione di nuovi package workspace

## Criterio di chiusura

- esiste un indice delle specifiche plugin-first
- esiste un documento fondativo M4.0 che sintetizza le decisioni core
- ogni specifica ha scope, decisioni, contratti e out-of-scope
- M4/M5 sono coerenti con la direzione plugin-first
- e chiaro quale parte del core implementare nella milestone successiva
- non restano riferimenti a domini applicativi come espansione del core
- non restano specifiche dominio dentro la milestone core

## Note

Questa milestone e intenzionalmente documentale.

La milestone successiva potra essere implementativa solo dopo aver chiuso queste
specifiche. Il primo candidato implementativo deve essere un blocco core della
piattaforma, non un plugin dominio.
